# 模拟渲染方法

目的：把修复后的 J15T 与 J16 放到一致视角下检查。无需制作修复前对照，也不在图上叠加数据库短线。

## 几何和取景

1. 从本地经过审查的三角形/UV 导出读取顶点、UV、part 与 island；保留来源三角形编号。静态诊断不能重建游戏动画与损伤状态。
2. 原生坐标为 X 向机头、Y 向上、Z 向左。转换到 Blender 时使用 `(X,Z,Y)`，注意该交换反转手性，三角形绕序和法线需一致处理。不得把原生 Y 误当成水平轴。
3. 比较双方使用相同相机变换、正交比例、投影矩阵、图像宽高和色彩管理。不得逐图自动缩放主体，否则接缝位置失去可比性。
4. 先检查六个轴向与八个斜向。局部补看鸭翼从下往上、进气口内部、垂尾内外侧与操作面、尾根、中央柱体、喷口。
5. 世界点投影必须使用实际相机矩阵或 Blender 的 world_to_camera_view。不要手写“正交比例等于图高”的换算；横向画幅下这种假设曾造成像素定位偏差。

`config/tools/render_preview.py` 提供可复用的正交纯色纹理诊断入口；显式指定相机位置、观察目标和比例，相同参数用于双方。它只输出单模型模拟图和相机记录，不自动产生带标线图。

```powershell
blender -b --python config/tools/render_preview.py -- --geometry aircraft/j15t/j_15t_c/geometry.npz --texture PATH_TO_LOCAL_COLOR_TEXTURE --output preview.png --eye 0 20 0 --target 0 0 0 --scale 24
```

eye/target 参数使用原生坐标。直接使用外表面筛选网格会缺少部分遮挡体；正式局部核查应使用本地完整原始几何。仓库不含原始涂装，用户自行指定有权使用的贴图。

## 两类诊断

颜色定位用 Emission、Standard 色彩变换、固定曝光。这样可判断图案和面板线是否对齐，避免把灯光阴影误认成填充。

材质检查另做固定灯光/环境预览。先确认当前载具 shader 的打包通道，再解码法线。既有流程中 `_n` 的 G/A 用于切线法线，R/B 保留来源材质变化；不可把四个通道当作普通 RGB 法线，也不可将 R/B 直接假定为 Principled 的 roughness/metallic。图案搬运发生旋转或镜像时，法线切向分量必须随局部坐标系变换。

Blender 中性材质只支持法线方向诊断，不能证明 Dagor 下喷口金属反射正确。记录 Blender 版本、相机、分辨率、色彩管理、输入哈希和通道规则，最终由游戏内相同视角复核。

## 定位未知涂装区域

当发动机/进气道对应 UV 不明确时，可在独立临时测试贴图中放分区色块、编号和方向箭头，渲染后反查。使用不同尺度测试，再缩小到目标三角形。不要把诊断色块写入正式涂装；本次数据库短线完全不需要画出。

只有当材质绑定、可见面、UV 分区和纹素方向都确认后才实施填充。图像相似、单张正视图看起来正确、数据库连通或文件哈希一致，都不能替代斜角和游戏验证。
